# Student Course Registration System

A beginner-friendly REST API project using Java 17, Spring Boot, Spring Web, Bean Validation, Spring Data JPA, and H2. MySQL can be enabled with a profile.

## Features
- Register students for courses
- View all registrations and find one by ID
- Update a registration
- Delete a registration
- Search registrations by course name (partial, case-insensitive match)
- Field validation and consistent JSON error responses
- Duplicate protection for the same email + course combination (one student may register for different courses)
- H2 console for development and automated integration tests

## Requirements
- JDK 17 or later
- Maven 3.6+ (or use the Maven wrapper supplied by your IDE)
- Eclipse / IntelliJ IDEA / VS Code (optional)

## Run in Eclipse
1. Extract the project folder.
2. Choose **File → Import → Maven → Existing Maven Projects**.
3. Select the folder containing `pom.xml` and finish import.
4. Wait for Maven dependencies to download.
5. Run `StudentCourseRegistrationApplication.java` as **Java Application** or **Spring Boot App**.
6. The server starts at `http://localhost:8080`.

Alternatively, from the project directory run:
```bash
mvn spring-boot:run
```

## Default database: H2
The default database is in-memory. Data resets when the app stops. H2 console: `http://localhost:8080/h2-console`
- JDBC URL: `jdbc:h2:mem:studentdb`
- User: `sa`
- Password: leave blank

## Optional MySQL
1. Start MySQL and create the database:
```sql
CREATE DATABASE student_course_registration;
```
2. Set environment variables `DB_USERNAME` and `DB_PASSWORD` (or edit `application-mysql.properties`; avoid committing real credentials).
3. Run with the MySQL profile:
```bash
mvn spring-boot:run -Dspring-boot.run.profiles=mysql
```
Or set `spring.profiles.active=mysql` in your IDE run configuration. Never use the sample password in a real environment.

## API endpoints
Base URL: `http://localhost:8080/api/students`

| Method | Endpoint | Purpose | Success response |
|---|---|---|---|
| POST | `/api/students` | Register student | `201 Created` |
| GET | `/api/students` | View all | `200 OK` |
| GET | `/api/students/{id}` | Find by ID | `200 OK` |
| PUT | `/api/students/{id}` | Update registration | `200 OK` |
| DELETE | `/api/students/{id}` | Delete registration | `204 No Content` |
| GET | `/api/students/search?course=java` | Search by course | `200 OK` |

### Register request
`POST /api/students` with `Content-Type: application/json`
```json
{
  "studentName": "Abhiram S",
  "courseName": "Java Full Stack",
  "email": "abhiram@example.com",
  "age": 21
}
```
`studentId` is generated by the database; do not send it in the request.

### Example successful response
```json
{
  "studentId": 1,
  "studentName": "Abhiram S",
  "courseName": "Java Full Stack",
  "email": "abhiram@example.com",
  "age": 21,
  "registeredAt": "2026-10-28T10:00:00"
}
```
The timestamp is generated by the application, so the actual value will differ.

### More sample registrations
```json
{
  "studentName": "Priya Sharma",
  "courseName": "Spring Boot",
  "email": "priya@example.com",
  "age": 22

```

## Validation examples
Invalid request:
```json
{
  "studentName": " ",
  "courseName": "",
  "email": "wrong-email",
  "age": 17
}
```
Example response (`400 Bad Request`):
```json
{
  "timestamp": "2026-10-28T10:00:00",
  "status": 400,
  "error": "Validation Failed",
  "message": "Please correct the invalid fields",
  "fieldErrors": {
    "studentName": "Student name cannot be empty",
    "courseName": "Course name cannot be empty",
    "email": "Enter valid email",
    "age": "Age must be at least 18"
  }
}
```
A real timestamp is generated at runtime.

## Try with curl
Register:
```bash
curl -i -X POST http://localhost:8080/api/students -H "Content-Type: application/json" -d "{"studentName":"Abhiram S","courseName":"Java Full Stack","email":"abhiram@example.com","age":21}"
```
View all:
```bash
curl -i http://localhost:8080/api/students
```
Find ID 1:
```bash
curl -i http://localhost:8080/api/students/1
```
Update ID 1 (send all fields):
```bash
curl -i -X PUT http://localhost:8080/api/students/1 -H "Content-Type: application/json" -d "{"studentName":"Abhiram S","courseName":"Advanced Java","email":"abhiram@example.com","age":21}"
```
Search course:
```bash
curl -i "http://localhost:8080/api/students/search?course=java"
```
Delete ID 1:
```bash
curl -i -X DELETE http://localhost:8080/api/students/1
```

## Error handling
- `400 Bad Request`: invalid JSON or validation failures
- `404 Not Found`: requested registration ID does not exist
- `409 Conflict`: same email is already registered for the same course

## Automated tests
Run:
```bash
mvn test
```
Tests cover successful registration, blank name, invalid email, age below 18, missing ID, and duplicate course registration.

## Design notes
- DTO validation is used at the API boundary; entity constraints protect database columns.
- The ID is generated server-side.
- The duplicate rule is email + course, not email alone, because a student can register for multiple courses.
- The default H2 setup is for development/testing. Use MySQL for persistent local storage.
- `ddl-auto=update` is convenient for learning. For production, use database migrations and managed credentials.
